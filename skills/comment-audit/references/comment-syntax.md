# Finding comments

How Step 1 finds every comment, which languages are in scope, and which comments are machine-read and never touched.

## Method per language

Prefer a tokenizer, because it never mistakes `#` or `//` inside a string, a URL or a regex literal for a comment. Write any helper script in the audit folder, never in the repository.

| Language | Comment forms | Method |
|---|---|---|
| Python | `#` line; docstrings (the first string statement of a module, class or function) | `python3 -m tokenize -e <file>` lists `COMMENT` tokens. For docstrings, use `ast.get_docstring` and the node's line range |
| JavaScript, TypeScript (`.js .jsx .mjs .cjs .ts .tsx .mts .cts`) | `//`, `/* */`, `/** */` | The TypeScript compiler API (`ts.forEachLeadingCommentRange` and `ts.forEachTrailingCommentRange`) or ESLint's `sourceCode.getAllComments()` when the project has them installed. Otherwise use a scanner that skips string, template and regex literals |
| Go | `//`, `/* */` | `go/parser` with `parser.ParseComments`, which gives `file.Comments` |
| Rust | `//`, `/* */`, `///`, `//!` | A scanner that skips string, raw string and char literals. Doc comments are `///` and `//!` |
| Java, Kotlin, C, C++, C#, Swift, Scala, Dart, PHP | `//`, `/* */`, `/** */` (PHP also `#`) | A scanner that skips string and char literals (and text blocks, raw strings and verbatim strings) |
| Ruby | `#`, `=begin … =end` | `ruby -e 'require "ripper"; …'` (`Ripper.lex` gives `:on_comment` tokens), else a scanner |
| Shell (`.sh .bash .zsh`) | `#` | A scanner that skips quoted strings and here-documents. `$#` and `${#var}` are not comments |
| SQL | `--`, `/* */` | A scanner that skips quoted strings |
| CSS, SCSS, Less | `/* */` (SCSS and Less also `//`) | A scanner that skips strings and `url(...)` |
| HTML, Vue, Svelte templates | `<!-- -->`, plus the script and style blocks by their language | A scanner per block |

A file in another language is left out and listed under `Uncertainty:`. A scanner instead of a tokenizer is recorded in the audit as an approximation.

## Comment units

- A run of line comments on consecutive lines with nothing else on them is one unit.
- A block comment, doc comment or docstring is one unit, however many lines it spans.
- A comment after code on the same line is an inline unit. It has no own lines.
- **Own lines** are the lines that hold only comment text (and whitespace). A docstring's own lines are all the lines of the string statement.

## Machine-read comments

These get `M` IDs. They are counted, listed with the reason, and never edited, deleted or banned.

- **Directives** that tools read, for example:
  - Python: `# noqa`, `# type: ignore`, `# pragma: no cover`, `# pylint:`, `# fmt: off/on`, `# isort:`, `# mypy:`, `# pyright:`.
  - JS/TS: `eslint-disable…`, `eslint-enable`, `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `@ts-check`, `prettier-ignore`, `istanbul ignore`, `c8 ignore`, `v8 ignore`, `/// <reference …/>`, `@jsx`, `@jsxImportSource`, `webpackChunkName` and other bundler magic comments, `@vite-ignore`.
  - Go: `//go:build`, `// +build`, `//go:generate`, `//go:embed`, `//go:linkname`, `//nolint`, `//lint:ignore`, `// Deprecated:` paragraphs.
  - Rust: `// rustfmt::skip` style tool comments. `#[…]` attributes are not comments at all.
  - Others: `# frozen_string_literal:`, `# rubocop:`, `// swiftlint:`, `// NOLINT`, `// clang-format off`, `@SuppressWarnings` notes, `# shellcheck disable=`, `<!-- prettier-ignore -->`.
- **File headers:** a shebang, an encoding line (`# -*- coding: … -*-`), `SPDX-License-Identifier`, and a license or copyright block at the top of the file.
- **Generated-code markers:** `Code generated … DO NOT EDIT.`, `@generated`, `<auto-generated>`. A file carrying one is generated, so leave the whole file out of scope.
- **Types in comments:** Python type comments (`# type: int`). In a JavaScript file checked by TypeScript (`checkJs`, `// @ts-check`), JSDoc blocks that carry type tags (`@type`, `@param {…}`, `@returns {…}`, `@typedef`, `@template`).
- **Doc text something reads:**
  - Python docstrings holding doctests (`>>>`), docstrings read through `__doc__`, and docstrings that frameworks turn into help or schema text: Click, Typer and Fire commands, `argparse` descriptions built from `__doc__`, FastAPI and Django REST route docs.
  - Go example functions' `// Output:` and `// Unordered output:` blocks, which are test assertions.
  - Rust doc comments that hold code blocks, which run as doc tests, unless the block is marked `ignore` or `text`.

  When unsure whether a docstring is read, search for `__doc__`, `inspect.getdoc` and the framework decorators in the scope.

If deleting a comment makes a baseline check fail or lowers the number of tests passed (Step 6), it was machine-read after all. Restore it and move it here.

## Files left out by default

Generated files, vendored folders (`vendor/`, `third_party/`, `node_modules/`), build output (`dist/`, `build/`, `out/`), minified files (`*.min.*`), lockfiles, notebooks (`.ipynb`), Markdown and other docs, and config files (YAML, TOML, INI, JSON5). Include config files only when the user names them. Report each group and its file count.
